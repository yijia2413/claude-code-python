# 06 - 多任务守护进程监控模块

多任务守护进程监控模块（`daemon/`）是系统执行高耗时、异步或后台持续运行的开发与编译命令的核心管理系统。通过建立多并发进程生命周期管理器，该模块能够将长耗时开发命令（如持续构建、测试或启动服务）安全地转入后台守护运行，并提供精细化的实时日志流捕获和强杀控制。

## 2. 出口与入口函数接口说明 (API Interface)

### 2.1 派生并发后台任务 (`start_task`)
*   **入口函数**: `start_task(self, command: str, cwd: str) -> int`
*   **输入参数**:
    *   `command` (str): 剥离了末尾 `&` 的纯物理 shell 命令行。
    *   `cwd` (str): 目标工作路径。
*   **出口返回值**: `int`，分配给该守护任务的自增唯一任务 ID（例如 `1`、`2`、`3`）。
*   **副作用**:
    *   在主系统后台异步拉起一个新的 `subprocess.Popen` 会话。
    *   在本地磁盘创建 `~/.claude/tasks/<task-id>.log` 日志文件。

### 2.2 活跃后台任务状态拉取 (`list_tasks`)
*   **入口函数**: `list_tasks(self) -> List[dict]`
*   **输入参数**: 无。
*   **出口返回值**: `List[dict]`，字典列表。每个字典包含：
    *   `id` (int): 任务自增 ID。
    *   `command` (str): 命令行文本。
    *   `cwd` (str): 运行路径。
    *   `status` (str): 状态（`RUNNING`、`COMPLETED`、`FAILED`、`KILLED`）。
    *   `exit_code` (int / None): 子进程退出码，仅在已结束时存在。
    *   `pid` (int / None): 系统的物理进程 ID。
    *   `elapsed` (float): 该任务从启动到当前累计运行的秒数。
*   **副作用**: 无。

### 2.3 后台任务强杀控制 (`kill_task`)
*   **入口函数**: `kill_task(self, task_id: int) -> bool`
*   **输入参数**:
    *   `task_id` (int): 目标强杀任务的 ID。
*   **出口返回值**: `bool`，`True` 表示成功执行强杀且进程已死；`False` 表示操作失败或任务不存在/已提前结束。
*   **副作用**:
    *   直接向目标子进程及其包含的所有衍生进程派发强杀信号。

## 4. 底层技术原理与核心逻辑设计

### 4.1 基于自增 ID 对并发 `Popen` 任务的管理
在重构版中，我们通过 **`TaskManager` 单例** 来负责在内存中管理所有活跃的后台任务。虽然系统底层的进程 ID（PID）是系统随机且庞大的，但为了方便人类在交互终端中高效地通过快捷指令调用，`TaskManager` 为每个后台进程统一生成一个自增的、易记的整数 ID（自 1 开始递增），使得在大模型或用户下发指令时，可以通过 `/logs 1` 或是 `/kill 2` 来极速交互，大大优化了 CLI 的整体操作效率。

### 4.2 Unbuffered Output 日志重定向冲刷机制
在 Python 中，当子进程输出被重定向到非 tty 管道（例如文件）时，默认会启用块缓冲模式（Block Buffering），导致输出在较长时间内无法写入日志文件。为了实现完美的**实时日志追踪（Real-time log tailing）**，重构版采取了以下两点设计：
- **测试/验证端**: 使用 `sys.executable -u` 参数启动 Python 后台子进程，强行开启无缓冲输出模式。
- **管理器读取端**: 在读取 `get_task_log` 前，显式调用进程及日志文件句柄的 `flush()` 方法，确保内存中的缓冲内容被立刻全部推送到物理磁盘上，保证了 `/logs <id>` 展示数据的 100% 实时性。

### 4.3 多平台防挂死与进程隔离机制
- 启动 `Popen` 时，指定参数 `start_new_session=True`（相当于在 macOS/Linux 上调用 `setsid()` 启动新会话）。
- 这使得后台运行的守护进程从 REPL 的会话组中彻底隔离出来。当用户在命令行键入 `Ctrl+C` 想要打断大模型的分析流时，该终端信号将绝对不会波及和杀死后台正在编译或测试的进程，消除了后台运行的任务因为主终端 Ctrl+C 误杀而崩溃挂起的隐患。
- 终止进程时，先温和地发送 `SIGTERM` (terminate) 以允许子进程在 1 秒内进行内存及快照的妥善保存和关闭；若子进程挂起无响应，则立即升级发送 `SIGKILL` (kill) 物理信号强行物理抹除，保障系统的高可用性。
